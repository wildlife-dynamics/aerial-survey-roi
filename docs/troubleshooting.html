Troubleshooting

Common issues encountered while configuring, running, or contributing to the Aerial Survey ROI Workflow, and how to resolve them. If your issue isn't listed here, open an issue on GitHub.

Configuration & Input

Workflow fails on ROI input

This workflow only supports polygon or multipolygon geometry — point and line files are not supported. Check your Define Region of Interest file in QGIS or similar to confirm its geometry type before uploading.

CRS error on load

The source file has no CRS assigned. Set an EPSG code before uploading (in QGIS: Layer Properties → Set CRS; in Python: gdf.set_crs('EPSG:4326')). Once loaded, the ROI is reprojected to EPSG:4326 automatically — but only if a CRS is present to begin with.

URL field validation error / file not found

The Define Region of Interest URL must be a direct download link, not a preview or share page — e.g. a Dropbox link needs dl=1 (or the workflow's own handling of dl=0), not a browser preview URL. If the link requires authentication, it won't be reachable from the workflow runner.

Basemap tiles don't load, or the background map is blank

The Basemap Layers URLs are user-editable. If you changed either the ESRI World Hillshade or World Street Map layer away from its default, confirm the new tile URL follows the standard {z}/{y}/{x} template and is reachable from the machine running the workflow.

Survey Lines & Output

No lines generated / blank survey lines layer

The Line Spacing value is too large relative to the ROI's extent in the chosen direction — if spacing exceeds the ROI's cross-track width, transect generation returns an empty result and every downstream task is skipped rather than erroring. Reduce the spacing and re-run. As a rough guide: small ROIs (< 100 km²) usually want 500–1000 m spacing; large ROIs (> 1000 km²) can use 2500–5000 m.

Tasks show as "skipped" rather than completed

This is expected behavior, not an error. Every task shares a global skip policy: if any upstream GeoDataFrame is empty (any_is_empty_df), that task and everything depending on it is skipped (any_dependency_skipped) rather than crashing the run. Trace back to the first skipped task in the chain — usually the ROI load or the survey line generation — to find the root cause.

No outputs written / can't find results

All outputs are written to the directory specified by the ECOSCOPE_WORKFLOWS_RESULTS environment variable. Confirm it's set and points to a directory the workflow process can write to.

Blank HTML map when opened directly in a browser

Some browsers block local tile/resource requests opened via file:// due to CORS restrictions. Serve the output directory locally instead, e.g. python -m http.server 8080, and open the map through http://localhost:8080.

Contributing & CI

These apply if you're modifying the workflow itself (spec.yaml, test-cases.yaml, or the generated ecoscope-workflows-aerial-survey-roi-workflow/ directory) and opening a pull request.

Generated files differ from committed files in ecoscope-workflows-aerial-survey-roi-workflow

The generated workflow directory is out of sync with spec.yaml. Run the recompile script locally and commit the result:

pixi run --manifest-path pixi.toml --locked bash -c "./dev/recompile.sh --update"

Found wildcard version (*) in requirements or Found local file channel (file://) in requirements

In spec.yaml, every dependency under requirements must pin an exact version and use a remote conda channel — wildcard versions and local file:// channels are only valid for local development, not for CI using published packages.

VERSION.yaml (...) must be greater than main branch (...)

Bump MAJ/MIN/PATCH in ecoscope-workflows-aerial-survey-roi-workflow/VERSION.yaml so it's strictly greater than the version on main before opening or updating a PR.

test-cases.yaml must contain at least one test case

Every workflow requires at least one top-level entry in test-cases.yaml with a params block. See the existing all-grouper entry in that file for the expected format.

Workflow tests fail in CI but pass locally (or vice versa)

test.yml runs test cases against all of ubuntu-latest, macos-latest, and windows-latest. If a test only fails on CI, check whether it depends on network access to the ROI file's URL or on OS-specific path handling.
